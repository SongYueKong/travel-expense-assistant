# 支付金额识别

金额决策集中在 `engine/payment_amounts.py`，与 Windows OCR 的文字提取分开。所有计算使用整数分。

1. 从标签本行、右侧同一行或紧邻的下一行定位字段，不跨越下一字段。不使用金额在屏幕高度中的固定百分比。
2. 标记实付、净支付、订单、优惠、退款、余额、交易金额和记账金额。裸整数、时间和交易号不作为金额。
3. 无实付标签时，通过金额相对明细的位置、字号及支出符号寻找账单主金额，并核验支付状态；多个冲突金额保留待核对，不按最大金额或最大字号强选。
4. 校验订单、优惠和实付关系；人民币银行记录要求交易金额与记账金额一致且有支出方向。退款扣减必须有明确一致的状态和记录，净额不得重复扣款。
5. 数字模糊时仅对有用途依据的金额区域补识别，保留全部尝试；不能直接把不确定字母替换成数字。

识别结果保持兼容 `ocr.paymentCandidate.cents`。新增 `amountCandidates` 保存金额用途、来源文字和框位置，`amountDecision` 保存识别/待核对状态与原因，`amountRecognitionVersion` 标记当前规则版本。它们是识别证据，不是人工确认记录，也不改变既有支付匹配、日期容差和汇总口径。

界面的“查看金额依据／候选”提供原图框选。用户主动填入的数值先留在编辑草稿，保存关联后才成为人工修正。余额、订单额、优惠及退款不提供直接填入实付按钮；部分退款提供经过核验的净支付。旧记录在重新识别后取得这些依据。

未知字段、无法确定的结算关系和冲突证据仍需人工核对。扩展时优先增加字段含义和交叉校验，不增加某手机型号的坐标模板。

验证按 `AGENTS.md` 运行完整回归。公开合成测试位于 `engine/test_payment_semantics.py`；真实原件及位置/缩放变体均为本地私有测试数据，不进入 Git 或发行包。
